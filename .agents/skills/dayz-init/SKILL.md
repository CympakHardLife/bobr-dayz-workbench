# Подготовка рабочего места

Вызови preflight и doctor: доступность инструментов сборки и исправность памяти
проверяются отдельно. Сверь выбранный source root, сторону client/server,
output, DayZ Tools и наличие ванильных sources. Старый проект не выбирай по
последнему пути в памяти. Наличие EXE означает доступность файла, рабочий запуск
проверяется отдельно.

Отсутствующий WorkDrive не ломает поиск/статический анализ. Не монтируй его
поверх занятого диска. Используй явно настроенную рабочую папку; соседние данные
не менять. workdrive выдаёт status/plan; установка и mount не следуют из preflight.

На Windows до запуска Python проверь полный путь существующего интерпретатора.
Не вызывай непроверенные python/py из PATH: WindowsApps/install-manager alias
может автоматически скачать и установить runtime. В subprocess используй
sys.executable; каталоги TEMP/TMP задавай внутри согласованной области данных.

Результат — доступные операции и точная причина каждой недоступной. Для переноса
исправляй только конфиг профиля, затем адресно проверяй зависимости. Не запускай
игру ради проверки установки редактора.

Команды вызываются из корня репозитория через `.\bobr.ps1`; точный синтаксис —
`commands` и `<команда> --help`. Общие правила — AGENTS.md.
