# Команда разработки

Используй `task --help` и [протокол](../../../workbench/TASK_PROTOCOL.md).
План содержит acceptance, depends_on и write_paths каждого задания.
Пересекающиеся правки назначай одному владельцу или выполняй последовательно.
Делегируй там, где параллельная работа действительно независима.

Получай next/brief и передавай помощнику профиль, границы и релевантные sources.
JSON-задание не вызывает модель: нужен фактический инструмент делегирования.
Исполнитель сдаёт summary/evidence/checks/limitations. Другой reviewer проверяет
acceptance; reject возвращает задачу автору с конкретным дефектом.

После изменения evidence обнови зависимые результаты. Перед сменой чата сохрани
run ID/следующий шаг; продолжай существующий план. Итоговая приёмка проверяет
конечный артефакт, а не число ответивших помощников. Ограничь бессмысленные
повторы: если новых данных нет, зафиксируй причину и измени подход.

Команды вызываются из корня репозитория через `.\bobr.ps1`; точный синтаксис —
`commands` и `<команда> --help`. Общие правила — AGENTS.md.

Для игровых acceptance используй `scenario-results --spec ... --results ...` по
TASK_PROTOCOL: сверяются source/PBO/evidence SHA, сторона и START/terminal.
Пропущенное остаётся not_run; начатое без завершения — fail. Проверяется
заявленный отчёт, а фактическое наблюдение оценивает независимый reviewer.
Для полных статических проверок передавай в `gate` выбранные `--type-db` и
`--types-from` вместе. Без них проверки типов явно отмечаются как skipped.
