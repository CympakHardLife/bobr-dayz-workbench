# Сборка и проверка PBO

Прочитай help команд build, inspect-pbo и deploy. Сначала lint и адресные static
checks изменённого Enforce. Output направляй в build-папку, temp — в настроенном data-root;
изолируй output от установленного клиента/сервера. Проверь список stage inputs,
исключения, CfgMods и правильную сторону payload.

Проверь exit code, свежесть и размер нового файла, entries/prefix и соответствие
входам в пределах поддерживаемого readback. Прежний PBO не доказывает успешную
новую сборку. Успех EXE без нового проверенного артефакта останавливает передачу.

При расхождении результата сверь цепочку: изменённый исходник → stage той же
сборки → entry внутри PBO → SHA установленного PBO в каждом разрешённом target.
Сохрани build receipt; SHA из него должен совпасть с переданным и установленным
файлом. deploy проверяет переданный PBO, но сам не связывает его с build receipt.
Проверяй также отсутствие удалённых/неожиданных entries. Разрешённые generated
entries перечисляй отдельно; сжатое/преобразованное содержимое не считать
подтверждённым по SHA исходного текста. Имя и время PBO не заменяют эту сверку.
Если отчёт не указывает packing/readback coverage, содержимое считать непроверенным.

Для подозрения на кеш сначала прочитай команду, session/build.log и фактический
stage/temp. Для backend addonbuilder pipeline задаёт отдельный -temp и TEMP/TMP/TMPDIR; чужое правило
именования кеша не доказывает путь здесь. Не очищай общий TEMP. Если нужна
очистка конкретной сессии, проверь абсолютный путь, принадлежность задаче и
отсутствие работающего сборщика; сохрани нужные доказательства до удаления.

Deployment — только конкретный PBO в точный разрешённый target с SHA-сверкой.
Не копируй всё по маске и не удаляй соседние моды. Подпись выполняй по действующему
поручению владельца; старый bisign не подпись нового payload. Итог различает lint/упаковку/readback/deploy/
Enforce/game. Ключи, .env, cache и player data не входят в stage.

Команды вызываются из корня репозитория через `.\bobr.ps1`; точный синтаксис —
`commands` и `<команда> --help`. Общие правила — AGENTS.md.
