# Контракт устойчивых данных

Найди реальные OnStoreSave/OnStoreLoad и порядок super в owning классе. Схема
зависит от фактического engine/provider contract, не названия метода.

До кода определить версию/порядок полей/defaults/диапазоны/устойчивые ID,
поддерживаемые старые версии и отказ на неизвестную новую. Load отделить от
активации timers/RPC. Частичное чтение не должно уничтожать прежнюю запись.

Сценарии: новая запись save/load; старая поддерживаемая миграция; неполная и
повреждённая запись; повторный load/respawn без duplicate callbacks; reconnect/
restart. JSON-тест модели не подтверждает engine serialization. Для игрового
теста отдельная копия storage без player data. В итог входят схема/миграция,
forward/backward limits и rollback; downgrade без обратимого формата не обещать.
