# Проверки результата

Определи acceptance до теста. Ступени: API review, static checks, конфиги/ресурсы,
PBO/readback, Enforce, client/server сценарий, reconnect/restart, нагрузка.
Каждой нужны coverage, статус и skipped; частичный успех не расширяй на всё.
check выполняет собственные static checks, session-plan готовит сценарий.

Для AI используй [сценарии](references/behavior.md), для UI — размеры экрана и
ввод. Зафиксируй build hashes и начальную точку сравнения. Повторяй проверки после
затрагивающей правки/нового сбоя, а не ради роста счётчика.

Результат содержит команду, вход/версию, артефакт и пределы. Непроведённая ступень
остаётся открытой. Чистый лог не доказывает срабатывание механики; пользовательское
подтверждение относится к конкретной сборке/сценарию. Запуск игры/сервера —
отдельное действующее поручение, подготовленный сценарий не означает исполнение.

Команды вызываются из корня репозитория через `.\bobr.ps1`; точный синтаксис —
`commands` и `<команда> --help`. Общие правила — AGENTS.md.
