# Передача и выпуск

Сверь release help и health проекта. Зафиксируй версию/hashes, client/server PBO,
load order/providers и checks. Старый успешный тест относится к старому hash.
Новый архив не превращает непроверенную сборку в runtime-ready.

Allowlist пакета: выбранные файлы, README установки/использования, changelog,
classnames/checksums. Серверный комплект — необходимые CE entries/подключения
и публичные bikey по задаче. Ключи/cache/profiles/player storage/.env исключить.
Старый bisign не включать как подпись нового PBO; владелец подписывает сам.

При передаче самого Workbench используй нейтральные templates памяти вместо
личного профиля. Проверь запуск из чистого Git clone: ignored generated configs
и память должны создаваться настройщиком. Примеры команд выполни с теми же
ограничениями путей, что применяет код; не подменяй эту проверку чтением README.

Сохраняй реальные авторство/лицензии перенесённых компонентов. Изучение source
не даёт права перепубликовать его целиком. Проверь CRC/entries/SHA и восстановление
в отдельную папку. Результат — архив/receipt/ограничения/первый запуск; это не
публикация в Workshop.

Команды вызываются из корня репозитория через `.\bobr.ps1`; точный синтаксис —
`commands` и `<команда> --help`. Общие правила — AGENTS.md.
