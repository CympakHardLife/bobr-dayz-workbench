# Bobr DayZ Workbench 2.0.4

Переносимая система разработки модов DayZ: предметные навыки, профили
специалистов, сохраняемые задачи, поиск по проверяемым источникам, статические
проверки и упаковка PBO. Автор и владелец проекта — Cympak.

В релиз входят **27 навыков, 22 профиля специалистов и 38 команд CLI**.
Профили задают обязанности; фактическое делегирование выполняет агент через
инструменты хоста. Файлы профилей сами не запускают модели.

## Установка

Нужны Windows и уже установленный Python 3.11+ со стандартной библиотекой.
pip-пакеты для базовых команд и тестов не требуются. Используй проверенный
существующий `python.exe` по полному пути. Короткие имена `python`/`py` могут
попасть в WindowsApps/pymanager alias и вызвать установку Python; для первого
запуска их не используй. Если интерпретатора нет, остановись и установи его
отдельно в выбранное тобой место.

Распакуй весь релиз в отдельную папку и выполни из её корня:

```powershell
$pythonPath = Read-Host "Абсолютный путь к проверенному установленному python.exe"
if (-not [System.IO.Path]::IsPathRooted($pythonPath)) { throw "Нужен абсолютный путь" }
$pythonPath = (Get-Item -LiteralPath $pythonPath -ErrorAction Stop).FullName
if ($pythonPath -match '[\\/]WindowsApps[\\/]' -or [System.IO.Path]::GetFileName($pythonPath) -in @('py.exe', 'pymanager.exe')) { throw "Нужен установленный интерпретатор, не Windows alias" }
& $pythonPath --version
& $pythonPath -B -X utf8 configure.py
& $pythonPath -B -X utf8 bobr.py doctor
& $pythonPath -B -X utf8 bobr.py commands
```

`--data-root` необязателен: первая настройка без него использует `.local`
внутри проекта. Настройщик создаёт локальные конфиги, каталоги данных и снимок
памяти. Он ничего не скачивает, не устанавливает службы, не монтирует диски
и не запускает игру. Подробности — [INSTALL.md](INSTALL.md).

## Использование

```powershell
& $pythonPath -B -X utf8 bobr.py route --query "Добавить повторную реакцию ботов на голос"
& $pythonPath -B -X utf8 bobr.py team list
& $pythonPath -B -X utf8 bobr.py task --help
& $pythonPath -B -X utf8 bobr.py build --help
& $pythonPath -B -X utf8 bobr.py health
```

На Windows те же команды доступны через `./bobr.ps1`. `commands` и `--help`
показывают действующий синтаксис. Псевдонимы `/dayz-*` относятся к CLI;
регистрация одинакового меню команд во всех чатах не входит в релиз.

Для существенной задачи основной агент выбирает роли, сохраняет план,
выдаёт краткие задания и принимает результат через отдельного проверяющего.
Workflow учитывает зависимости, владение файлами между запусками, авторов
изменений и актуальность доказательств. Actor — идентификатор участника workflow,
а не средство аутентификации человека.

## Новое в 2.0.4

- StarDZ Wiki подключается как отдельный корпус: безопасный импорт выбранных
  107 файлов закреплённой версии, 106 текстов в поиске, проверка SHA и provenance.
- `configure.py --wiki-root ...`, `search --scope wiki` и тема `community-wiki`
  работают с путями владельца. Загрузка выполняется только явным `--download`;
  можно использовать свой архив. Установки модели/служб не нужны.
- В навыки добавлены адресные оговорки по RPC, UI, JSON, очередям, Human/Infected
  API и звуку. Адаптированные документы выделены под CC BY-SA 4.0; корпус и
  сторонние программы в ZIP не включены. [Подключение и уроки](docs/WIKI_GUIDE.md).

## Возможности 2.0.3

- `scenario-results --spec ... --results ...` проверяет отчёт сценариев: SHA
  исходников, PBO и evidence, сторону и последовательность START → PASS/FAIL.
  Пропущенный сценарий получает `not_run`, незавершённый — `fail`.
- `gate --source ... --type-db ... --types-from ...` запускает все шесть
  существующих статических проверок через Core. Ошибка блокирует сборку.

Схема отчёта и примеры — [TASK_PROTOCOL.md](workbench/TASK_PROTOCOL.md). Проверка
отчёта контролирует целостность заявленных данных; наблюдение в игре и смысл
evidence оцениваются отдельно. Чужой код и зависимости не добавлены.

## Возможности и границы

| Область | Реализация |
|---|---|
| Разработка | Навыки по Enforce, config, UI, звуку, AI, ресурсам и совместимости |
| Задачи | DAG, claim/brief/submit/review/reopen, SHA доказательств |
| Проверки | Лексические gates, ресурсы, API snapshot/diff, CE и логи |
| Сборка | Детерминированная несжатая упаковка PBO стандартной библиотекой |
| Доставка | Отдельный план, явный запуск, точные разрешённые каталоги назначения |
| Память | Файловые карточки, experience, ручные snapshot/verify |
| Поиск | Ограниченные выдержки, provenance, SHA и производный кеш |
| Модель | Необязательный локальный планировщик запросов из внешних файлов |

Builtin PBO выполняет **pack-only**: `config.cpp` остаётся текстом, Binarize и
Enforce-компиляция не выполняются. Проверки упаковки и Python-тесты не доказывают
работу мода в игре, совместимость load order или производительность сервера.
Native инструменты DayZ Tools подключаются отдельно; их наличие и результат
проверяются на конкретной машине.

Модель, llama.cpp, игра, сервер, DayZ Tools, сторонние моды и большие корпуса
исходников в лёгкий релиз не включены. Без корпуса соответствующий поиск
недоступен; без модели остаются файловая память и обычный поиск по подключённым
источникам. Адаптеры Pinecone, Chroma, Milvus, PlugMem, Mem0 и Letta отсутствуют.

Память сохраняет записанные знания и договорённости. Она не переносит веса
модели, скрытое состояние чата или каждую прежнюю реплику. Кеш производен
от источников; проценты экономии оплачиваемых токенов не заявлены.

## Структура

| Путь | Назначение |
|---|---|
| `configure.py`, `bobr.py`, `bobr.ps1` | Настройка и запуск CLI |
| `.agents/skills/` | Предметные навыки и узкие проверки |
| `.codex/agents/` | Профили специалистов |
| `tools/` | Собственные инструменты и тесты |
| `workbench/` | Каталог команд, протоколы и локальная конфигурация |
| `core/`, `memory/`, `refs/` | Конфигурация поиска, карточки и указатели |
| `templates/memory/` | Версионируемые нейтральные шаблоны PROFILE, CURRENT и experience |
| `tests/` | Общий вход для тестов переносимого пакета |
| `.local/` или data-root | Проекты, runs, отчёты, builds, temp и cache |

Рабочие данные и внешние зависимости отделены от исходников. Секреты, ключи
подписи и данные игроков не добавляются в репозиторий. Загрузка, публикация
и подписание модов требуют отдельного решения владельца.

Личные `memory/PROFILE.md`, `memory/CURRENT.md`, `memory/experience.json`
создаются настройщиком из шаблонов при отсутствии и не включаются в Git.
Существующая память сохраняется; явный `--owner` заменяет профиль по твоему выбору.

## Проверка

Из корня полного переносимого пакета:

```powershell
& $pythonPath -B -X utf8 -m unittest discover -s tests -v
```

GitHub workflow проверяет Python-код на Windows без игры, сервера, модели и
native Tools. Успешный CI относится к этим проверкам, а не к игровому runtime.
История изменений — [CHANGELOG.md](CHANGELOG.md).
Обезличенный отчёт локальных проверок — [workbench/VALIDATION.json](workbench/VALIDATION.json).
