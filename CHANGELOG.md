# Изменения

## 2.0.5 — 2026-11-17

- Проверка состава PBO перед продвижением теперь отклоняет неизвестные лишние
  entries; разрешённые результаты генерации AddonBuilder выделяются в receipt.
  Регрессии проверяют старый script payload, неподходящие config entries и
  сохранение прежнего output при отказе. Это проверка инвентаря, не Enforce.
- Уточнены навыки сборки, assets и логов: сверка build receipt с установленным
  SHA, реальные stage/temp вместо предположения о кеше, различающая проверка
  гипотезы и её supersedes, единицы/оси/габариты модели и диагностика изображения.
- Из личных справочных материалов приняты общие проверяемые инженерные приёмы.
  Их тексты, память, пути, имена, программы и неподтверждённые запреты не включены.

## 2.0.3 — 2026-11-17

- Добавлена команда `scenario-results` для проверки локальных заявленных
  результатов сценариев. Контракт связывает отчёт с source/PBO SHA256, стороной,
  START и PASS/FAIL; проверяет evidence SHA и отклоняет drift, чужие ID и поля.
  Пропущенное получает `not_run`, START без завершения — `fail`. Команда только
  читает файлы: не создаёт history и не запускает игру, процессы или сеть.
- `gate` принимает `--type-db` и `--types-from` парой и запускает шесть полных
  static gates через существующий Core.check. Провал останавливает дальнейшие
  CfgConvert/сборку. Без пары остаётся прежняя проверка формы с явным skipped.
- По независимому ревью добавлена повторная проверка evidence после долгого
  source rehash; gate принимает только полный отчёт шести уникальных gates
  с целыми exit code 0, отклоняя противоречивый итоговый флаг.
- Обновлены протокол, навык orchestration и справка. В пакете 38 команд,
  27 навыков и 22 профиля. Дополнительные зависимости не требуются.
- Результат тестов относится к инструментам Workbench. Парсер отчётов не
  подтверждает правдивость наблюдения или игровое поведение конкретного мода.

## 2.0.2 — 2026-11-16

- Исправлена подтверждённая ошибка удалённого CI: `runner` недоступен в
  `jobs.<job_id>.env`, поэтому прежний workflow отклонялся до запуска jobs.
  Корень тестов теперь задаётся из `$env:RUNNER_TEMP` внутри PowerShell-шага;
  там же создаётся каталог и выполняется suite. Ограничения сверены по
  [официальной таблице contexts](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability)
  и [описанию RUNNER_TEMP](https://docs.github.com/en/actions/reference/workflows-and-actions/variables).
- Push-запуск ограничен веткой `main`; push тега больше не дублирует его.
  `pull_request` и `workflow_dispatch` сохранены согласно
  [правилам branch/tag filters](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushbranchestagsbranches-ignoretags-ignore).
- Версии `actions/checkout@v7` и `actions/setup-python@v7` сверены по их
  официальным [README checkout](https://github.com/actions/checkout) и
  [README setup-python](https://github.com/actions/setup-python).
- Изменены workflow, документация и метаданные выпуска; поведение инструментов
  не меняется. Актуальные локальные проверки отражены в `workbench/VALIDATION.json`.
  Удалённый CI подтверждается отдельным receipt после фактического завершения.

## 2.0.1 — 2026-11-16

### Переносимость

- Корень пакета определяется по расположению модулей. Удалены привязки рабочего
  процесса к личным путям и конкретным буквам дисков.
- Добавлен `configure.py`: необязательный data-root, отдельные пути
  Tools/корпуса/модели/runtime, manifest собственных файлов и снимок памяти.
- Базовая настройка и тесты используют Python 3.11+ и стандартную библиотеку;
  настройщик ничего не скачивает и не устанавливает фоновые службы.
- Данные, большие корпуса, бинарники и модель отделены от чистого релиза.
  Добавлены инструкция установки и Windows CI для переносимых тестов.
- Примеры первого запуска используют полный путь к проверенному существующему
  интерпретатору и отклоняют WindowsApps alias. Рабочие данные внутри репозитория
  ограничены `.local`; внешние зависимости задаются абсолютными путями без `..`.

### Проверки и исправления

- Pipeline получает разрешённые рабочие корни из конфигурации. Дополнительные
  каталоги требуют `approved_write_roots`; доставка — точного
  `deployment_targets`. Разрешённый родитель не разрешает дочернюю цель.
- Source drift сравнивает SHA и полный состав исходников перед продвижением
  сборки: добавленный во время упаковки скрипт делает результат устаревшим.
- Исправлена нормализация PBO prefix с завершающим разделителем и проверка
  собственных виртуальных ссылок без учёта регистра. Inspector проверяет
  изменение PBO во время чтения и прекращает хеширование при потере данных.
- Кеш повторно сверяет текст, SHA и происхождение. Повреждённое содержимое,
  подменённые метаданные или изменённый источник не принимаются за verified hit.
- Cursor логов сохраняет границу завершённых строк и учитывает переписывание
  файла; типовые credentials и идентификаторы маскируются в выдаче.
- Health отражает фактические результаты и ограничения. Упаковка, static
  gates и mocks не повышаются до Enforce-компиляции или игрового успеха.
- Сохранены ownership между runs, история contributors, запрет self-review и
  потеря актуальности зависимых результатов при изменении evidence.

### Состав и ограничения

- 27 предметных навыков, 22 профиля специалистов, 37 команд CLI.
- По умолчанию — детерминированная несжатая pack-only упаковка PBO.
  `config.cpp` остаётся текстом; Enforce и Binarize не выполняются.
- Native AddonBuilder остаётся отдельным явным backend. Успешный native runtime
  и совместимость конкретной установки игры данным релизом не заявлены.
- Модель и корпуса поставляются владельцем отдельно. Адаптеры внешних
  векторных и агентных систем памяти не реализованы.
