# Установка Bobr DayZ Workbench 2.0.2

## Требования

- Windows и уже установленный Python 3.11+ с `sqlite3` и `unittest` из стандартной библиотеки.
- Полный переносимый пакет в отдельном локальном каталоге с правом записи.
- Отдельная папка для рабочих данных по желанию владельца.

Для базовой настройки и тестов pip-пакеты не нужны. DayZ Tools, игра, сервер,
корпус знаний, GGUF-модель и llama.cpp подключаются отдельно по необходимости.
Настройщик их не скачивает и не устанавливает.

## Первый запуск

Используй проверенный существующий `python.exe` по полному пути. WindowsApps
и pymanager могут обрабатывать короткие имена `python`/`py` и запускать
установку, даже если требовалась только проверка версии. Не используй эти
короткие имена для первого запуска. Если Python ещё нет, остановись и установи
его отдельно в выбранное тобой место; Workbench не выбирает диск установки.

Открой PowerShell в корне распакованного проекта:

```powershell
$pythonPath = Read-Host "Абсолютный путь к проверенному установленному python.exe"
if (-not [System.IO.Path]::IsPathRooted($pythonPath)) { throw "Нужен абсолютный путь" }
$pythonPath = (Get-Item -LiteralPath $pythonPath -ErrorAction Stop).FullName
if ($pythonPath -match '[\\/]WindowsApps[\\/]' -or [System.IO.Path]::GetFileName($pythonPath) -in @('py.exe', 'pymanager.exe')) { throw "Нужен установленный интерпретатор, не Windows alias" }
& $pythonPath --version
& $pythonPath -B -X utf8 configure.py
& $pythonPath -B -X utf8 bobr.py doctor
& $pythonPath -B -X utf8 bobr.py commands
```

Проверь, что `--version` показывает Python 3.11 или новее. В дальнейшем
используй ту же переменную `$pythonPath`. После настройки wrapper `bobr.ps1`
может использовать сохранённый путь; явный `BOBR_PYTHON` имеет приоритет.

Внешние пути указывай абсолютными, без компонентов `..`. Внутренние пути
пакета определяются по расположению скрипта. Настройщик отклоняет пути с `..`,
UNC, symlink/junction и приватные каталоги.

Без `--data-root` первая настройка использует `.local` внутри проекта;
повторная — прежний сохранённый data-root. Внутри репозитория данные разрешены
только в `.local` и её подпапках. Для другого каталога данных укажи внешний
абсолютный путь; он не может совпадать с корнем исходников или быть его родителем:

```powershell
$dataRootPath = Read-Host "Абсолютный путь к внешнему каталогу рабочих данных"
& $pythonPath -B -X utf8 configure.py --data-root $dataRootPath
```

Появятся `projects`, `tests`, `runs`, `reports`, `builds`, `temp`, `cache`.
Настройщик запишет `core/config.json`, `workbench/config.json`,
`workbench/research_config.json`, обновит собственный manifest и создаст снимок
памяти. Модель в чистом пакете выключена, deployment targets пусты. Игра,
сервер, сетевые запросы и службы этим действием не запускаются.

В Git хранятся нейтральные `templates/memory/PROFILE.md`,
`templates/memory/CURRENT.md`, `templates/memory/experience.json`.
Настройщик создаёт отсутствующие личные файлы с теми же именами в `memory/`.
Они генерируются локально и исключены из Git; существующие профиль, CURRENT
и записи experience при обычной повторной настройке сохраняются.

Имя владельца можно задать отдельно:

```powershell
& $pythonPath -B -X utf8 configure.py --owner "Имя владельца"
```

`--owner` заменяет `memory/PROFILE.md` кратким новым профилем.
`--assistant-name` задаёт имя помощника при такой замене. Перед изменением
существующего личного профиля сохрани нужные договорённости отдельно.

## Необязательные DayZ Tools

Для native backend укажи уже установленный официальный набор:

```powershell
$dayzToolsPath = Read-Host "Абсолютный путь к установленному DayZ Tools"
& $pythonPath -B -X utf8 configure.py --tools-root $dayzToolsPath
& $pythonPath -B -X utf8 bobr.py preflight
```

Само указание пути не устанавливает и не запускает Tools. `preflight` проверяет
конфигурацию и доступность файлов. Builtin PBO работает без них. CfgConvert,
AddonBuilder, Binarize и Enforce — разные этапы; успешная упаковка не означает,
что остальные выполнялись.

## Необязательная база знаний

```powershell
$knowledgePath = Read-Host "Абсолютный путь к подготовленному корпусу знаний"
& $pythonPath -B -X utf8 configure.py --knowledge-root $knowledgePath
& $pythonPath -B -X utf8 bobr.py doctor
```

Нужен подготовленный корпус с совместимыми индексами и manifest исходников,
а не произвольная папка ZIP. Параметр регистрирует корень, но не скачивает и не
индексирует материалы. Пустой или отсутствующий корпус остаётся недоступным.
Объёмные корпуса и права на них проверяются отдельно. Версия справочника
не определяет версию игры. Перед использованием API нужно проверять текущие
owning scripts, слой, сторону, зависимости и load order.

## Необязательная локальная модель

Подготовь отдельно GGUF-модель и совместимый executable llama.cpp. Укажи оба
файла одновременно по абсолютным путям:

```powershell
$modelPath = Read-Host "Абсолютный путь к существующей GGUF-модели"
$llamaPath = Read-Host "Абсолютный путь к проверенному llama.cpp executable"
& $pythonPath -B -X utf8 configure.py --model $modelPath --llama $llamaPath
```

Настройщик вычисляет и сохраняет SHA256 обоих файлов. Для сравнения с заранее
проверенными значениями используй `--model-sha256` и `--llama-sha256`.
`--runtime-manifest` необязательно указывает существующий manifest runtime.
Модель крупнее 1.5 GB отклоняется текущим настройщиком. Совместимость конкретного
GGUF/runtime и его лицензия проверяются владельцем отдельно.

Модель вызывается при явном выборе модельного поиска. Она составляет план
запросов; факты должны подтверждаться исходниками. Настройка не запускает
фоновую модель и не отправляет память в облако. Для отключения:

```powershell
& $pythonPath -B -X utf8 configure.py --disable-model
```

Без параметров модели повторная настройка сохраняет ранее подключённую модель.
Внешние файлы в Git и лёгкий архив не копируются.

## Проверки и работа

```powershell
& $pythonPath -B -X utf8 -m unittest discover -s tests -v
& $pythonPath -B -X utf8 bobr.py health
& $pythonPath -B -X utf8 bobr.py route --query "Проверить зависимости нового мода"
& $pythonPath -B -X utf8 bobr.py task --help
```

Тесты используют изолированные fixtures и mocks native инструментов. При
необходимости задай `BOBR_TEST_ROOT` абсолютным путём отдельной папки тестов.
Заранее создай выбранный каталог, если переменная задана вручную.
CI использует тот же вход unittest на Windows; файл workflow не означает,
что удалённый прогон уже состоялся.

Открой корень проекта в рабочем хосте агента и начни с `AGENTS.md`.
Профили `.codex/agents` и навыки `.agents/skills` — часть проекта. Поддержка их
обнаружения и делегирования зависит от инструментов хоста. JSON-план сам
по себе не создаёт работающих помощников.

## Сборка и доставка

Синтаксис операций — `build --help`, `gate --help`, `inspect-pbo --help`,
`deploy --help`. Builtin создаёт несжатый PBO, проверяет структуру, хеши и
актуальность состава исходников. Он не преобразует `config.cpp`, не выполняет
Binarize и не компилирует Enforce. Игровое поведение проверяется отдельно.

Рабочая запись разрешена только в настроенных рабочих корнях и
`approved_write_roots`. Для `deploy --run` нужен **точный каталог** в
`deployment_targets` файла `workbench/config.json`; разрешённый родитель не
разрешает дочерние каталоги. План без запуска показывает блокировку неизвестной
цели. Замена требует отдельного `--replace`; старые подписи проверяются.
Ключи подписи не читаются, подпись автоматически не создаётся.

## Повторная настройка и перенос

`configure.py` заново формирует локальные конфиги. Если ты вручную добавлял
`deployment_targets`, дополнительные write roots или пути игры/сервера,
сверь их после повторной настройки. Непустая experience-память не удаляется:
при смене её корня настройщик требует отдельной миграции. Не обходи эту
проверку очисткой памяти ради успешного запуска.

На другой машине заново настрой пути, затем проверь `doctor`, `preflight`,
`health`. Прежняя проверка не подтверждает новый runtime. Если snapshot не
создался, настройщик вернёт ошибку даже после записи конфигов; исправь причину
и повтори snapshot/verify. `--no-snapshot` пропускает этот шаг явно и не
означает, что память проверена.

включаются в исходный репозиторий. Права и внешние материалы — [LICENSE](LICENSE)
